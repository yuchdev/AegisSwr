## 🔍 1.1.1 Inventory of Monolithic Windows Dependencies

The first task is to isolate and catalog every Windows-specific operating system hook, API, and binary utility buried in the `WinCrashAnalyzer` codebase. This creates a clear decoupling map for the cross-platform version.

### Dependencies to Map and Abstract:

* **Engine & Symbol Drivers:** Document how the prototype instantiates Windows debugging tools (e.g., relying on `cdb.exe`, `ntdll.dll` hooks, or wrapping `dbghelp.dll` to read minidumps).
* **System Event Querying:** Catalog any dependencies on Windows Event Logs (`EvtQuery` APIs) or automated PowerShell scripts parsing local machine event viewers.
* **Platform-Specific Enums:** Extract the internal lookup tables for Windows Structured Exception Handling (SEH) codes—such as `0xC0000005` (Access Violation) or `0xC0000094` (Integer Divide by Zero)—so they can be generalized into a platform-agnostic fault dictionary.

## ⚠️ 1.1.4 Gap & Debt Mapping (The Bridge to Aegis SWR)

The audit concludes with an official Gap Analysis Report. This document flags the conceptual vulnerabilities of the prototype that the multi-agent design intends to solve.

* **Tunnel Vision Vulnerability:** The prototype's single-prompt architecture takes the first plausible conclusion the LLM generates without challenging its validity. This confirms the product requirement for a dedicated **Skeptic Agent** to debate alternative system hypotheses.
* **No Discarded Rationale:** The prototype only outputs its final guess, dropping the intermediate steps. This highlights the need to capture the internal multi-agent dialogue as an editable **Investigator's Rationale** audit trail for users.
* **Silent Failures:** The prototype struggles with non-crash scenarios (e.g., a frozen background service that logs text but does not drop a `.dmp` file). This gap defines the expansion scope for the **OS Kernel** and **Log Historian** agents in Phase 3.
